## 17:10 — Загрузка файлов: аватар пользователя (любая роль) + фото объявления фермера

- Что сделано: Пользователь спросила, почему фермер не может прикрепить фото к товару и почему ни у кого (админ/фермер/покупатель) нет аватарки — оказалось, в проекте вообще не было ни одного эндпоинта загрузки файлов (`IFormFile` не встречался нигде), хотя `wwwroot/uploads/listings/` уже создавалась в `Program.cs`, а `ProductImage.ImageUrl`/`CreateProductImageDto` принимали только готовую строку-ссылку. Реализовано полноценно, с учётом стиля остального проекта (Result/ErrorType, try/catch+logger в сервисах, Repository/Service/Controller-слои):
  1. **Абстракция хранения файлов** — `IFileStorageService` (Application/Interfaces/Services: `SaveAsync(Stream, fileName, subFolder) → url`, `Delete(url?)`), реализация `LocalFileStorageService` — **в WebApi, не в Infrastructure**, т.к. зависит от `IWebHostEnvironment` (тот же принцип, что уже был закреплён для `ICurrentUserService`: ASP.NET Core-specific концепции не протекают в Application). Пишет в `wwwroot/uploads/{subFolder}/{guid}{ext}`, отдаётся уже существующим `app.UseStaticFiles()`.
  2. **`FileUploadValidator`** (Application/Validators) — общее правило для обоих сценариев: jpg/jpeg/png/webp (те же форматы, что уже были в `ProductImageValidator` для строчных URL, раздел 8.8 ТЗ), до 5 МБ.
  3. **Аватар** — `User.AvatarUrl` (новое поле, миграция `AddAvatarUrlToUser`), `IUserService.UploadAvatarAsync`/`DeleteAvatarAsync` (старый аватар удаляется с диска при замене), `AvatarDto`, `AvatarUrl` добавлен в `GetUserDto` и `AuthResponseDto` (значит, отдаётся сразу при логине/регистрации). Самообслуживание для **любой** роли — но `UserController` целиком `[Authorize(Roles = "Admin")]`, а несколько `[Authorize]` на классе+методе в ASP.NET Core комбинируются через AND, а не перекрывают друг друга, так что открыть один метод для всех ролей оттуда нельзя. Поэтому — новый `MeController` (`POST/DELETE /api/me/avatar`, просто `[Authorize]`), `UserId` берётся из `ICurrentUserService.UserId` (JWT-claims), в маршруте `{id}` нет вообще (раздел 16 ТЗ — не принимать UserId от клиента).
  4. **Фото объявления** — `IProductImageService.UploadAsync(productListingId, isMain, Stream, fileName, size)`, новый `POST /api/product-images/upload` в уже существующем `ProductImageController` (остался под тем же `[Authorize(Roles = "Farmer,Admin")]`, без владельческой проверки — как и остальные методы этого контроллера сейчас, ownership-проверок там в принципе ещё нигде нет, не стала вводить новый паттерн внутри чужой правки). Лимит 5 фото на объявление (раздел 8.8 ТЗ) — вынесен в переиспользуемый приватный метод, использован и в старом `CreateAsync`, и в новом `UploadAsync`. `DeleteAsync` теперь дополнительно чистит файл с диска через `IFileStorageService.Delete` (раньше просто удалял строку из БД — имело смысл, пока `ImageUrl` был только внешней ссылкой).
  5. `IFormFile` — ASP.NET Core-specific тип, не может быть в Application DTO — под него два маленьких request-класса в новой `MarketTJ.WebApi/Models/` (`UploadAvatarRequest`, `UploadProductImageRequest`).
